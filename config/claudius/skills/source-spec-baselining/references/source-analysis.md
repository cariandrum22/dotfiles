# 原典の読取りと判断

## 原典同定・取得

文書名に加え、発行主体、版/改訂、言語、発行日、正式/草案の別を同定する。既存の取り込みが版を指定していれば、新版で旧引用を置き換えない。更新、廃止、移行推奨は別の関係として記録する。

入力ごとに、必要な範囲で次を保存する。

- requested URL、最終URL、取得日時、HTTP status、redirect、ETag等。
- raw保存先、byte数、SHA-256、文書内の版表示とそのanchor。
- working treeから取得した場合はcommit同一性と未commit差分の有無。既存変更の帰属を推測しない。
- cookies、認証header、署名付きURL等の秘密値を除いた方法。metadataのredactionと原文byte改変を混同しない。

取得成功とsource authorityを分ける。403本文、認証画面、catalogue entry、release告知、component一覧はそれぞれのsurfaceの観測であり、規格本文ではない。正式版の告知とpreliminary表示が矛盾すれば双方の根拠を保存する。原因やlatest採用を推測しない。

zero-resultのerrata検索もquery/版/取得日/取得物digestに束縛する。現在の結果を永久的なerrata不存在と扱わない。network取得と保存物のoffline再実行は区別する。

## 派生物と表示確認

PDF抽出、HTML可読化、改行正規化には変換器・版・設定とraw→derivedのdigest対応を付け、rawは残す。

- byte offsetはrawかderivedかを明示し、文字数とbyte数を混ぜない。
- LF行は補助座標。form feed、PDFページ、印字ページ、HTML elementは別に扱う。
- 表・図、改訂markup、アルゴリズムの段番号、脚注、上付/下付等が判断を左右する箇所は元表示を読む。抽出順の再現だけで表示の意味を確認したことにしない。
- 画像hashの一致と実際の画像読取りは別の記録。読まなかったページは未読として残す。

## 区画と読取り計画

区画は引用と読み範囲を追跡する単位であり、要求の最小単位や義務数と同一ではない。

全文が対象なら開始/終端、非重複、連続性を再計算する。空白等を区画外に残すならgapにもoffset/length/digestと理由を持たせる。選択範囲なら、その範囲内の被覆と外の未読を示す。空白以外の未説明gapを全byte被覆に含めない。

`read` は実読、`unread` は未読、`inherited` は既受理判断の継承として区別する。複数回の読取りunionと今回全体を読み直した主張を混同しない。全文・対応action・理由を並べた私有renderは有用だが、読了を自動証明しない。

全引用がread範囲内であることは機械検査できる。read範囲の全てにactionが必要という意味ではない。actionのない区画も導入文・共通条件・構造・履歴の意味を確認する。

## 要求判断

| 内容 | 守る境界 |
| --- | --- |
| actor / role | 文法読者、実装、producer、consumer、protocol作者等を混ぜない |
| actionと対象 | 動詞だけでなく、何に対する義務/許可かを保持 |
| strength | 大文字、小文字、binding prose、文法規則、NOTE等を区別 |
| trigger / exceptions | 条件、時点、profile、例外、否定、上位契約への委譲を保持 |
| anchor | 根拠文、表header、共通導入文、補助節に解決可能 |
| judgment / reason | sourceの明記と、作成者の解釈・設計を区別 |
| granularity | 束ねた場合はcompositeと残る分割可能性を明示 |

BCP14の適用宣言と用語を確認する。keyword一覧、見出し、目次、引用された歴史的MUSTは、それだけでは現行の別義務を作らない。小文字must/shall、表、文法、否定、例外、暗黙の共通条件も読む。modal語を含まない義務を走査から落とさない。

actor・強度・条件が異なる句は通常分ける。可読性だけのために条件を省かない。解釈にanchor外の節が必要なら補助anchorを追加するか、導出と引用範囲を明示する。

非action理由は構造、非規範の説明、履歴、別actionに保持された文脈などを区別する。履歴文に現在も有効な命令があれば対応先を示す。旧製品の欠陥/成功観測を今回の製品判断へ移さない。

## 参照、取り込み、errata

書誌のnormative/informativeラベル、語彙出現、実際の義務取り込み、版更新は別の記録にする。取り込みには呼出し側のrole/trigger、対象版、範囲、優先順位、未読依存を必要に応じて記録する。

未読は `target-unread`、版不明は `edition-open`、取得不能は `source-unavailable` 等、定義した語彙で示す。閉鎖条件を具体的なsource/判断へ結び付け、参照数一致で閉じない。

errataの公式status/type/本文/notesと、project側のdecision/reason/適用版を分ける。Verifiedでも対象原文への適用不整合や未検証の修正案があり得る。Rejectedを採用訂正として扱わない。overlayの有無を明示し、未採用時は原文を改変しない。

依存閉鎖が今回の元条件なら、必要な依存を残して完了にしない。一般義務の文言や作業対応の審査で、外部原文の精査が別工程と明示判断された場合は、その残件を当該工程へ割り当てる。関連する全てを無期限に今回の条件へ追加しない。

## ID・旧文・作業対応

stable IDは追跡子であり文言不変の証明ではない。修正時は旧/新内容とhash、変更field、追加/削除/分割/統合、参照更新、保持行を示し、旧版を保存する。

旧spanの包含から旧文と新義務の同値を導かない。文脈に依存した対応、多対一、異なる強度、免責、未解決の言い換え、旧証拠再利用を区別する。

例えば「再利用は検証対象」という原文を一般の再利用禁止へ言い換えない。適用契約が特定の操作で禁止を要求するなら、それを弱めず義務を契約へ結ぶ。一般文言の忠実性、具体的な適用命題、実装による充足を別に判断する。

義務→作業対応は、対応先IDの存在とactor/条件/証拠型の保持を照合する。上位作業のmethod/owner欄が定型文なら限界を開示する。詳細な証明設計・担当確定が別工程でも、未割付の義務を隠す理由にしない。
